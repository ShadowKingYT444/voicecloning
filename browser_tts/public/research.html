Research note · October 2026

Small speech models,
inside the browser.

Zero-shot voice cloning in a browser is technically possible. This page tests one narrow route: a quantized Chatterbox Nano conversion, a short audio reference, and WebGPU inference on one device.

What “zero-shot” means here

The browser model receives a short reference recording at run time. It extracts speaker features and conditions new speech on those features. The site does not fine-tune a new speaker model. It uses an independent community ONNX conversion of the public Nano model, not this repository’s locally fitted adapter.

This is the design for a zero-shot workflow. Browser inference and output quality still need direct verification on this host.

Why the model is split into four graphs

  1. The speech encoder turns the reference WAV into audio and speaker features.
  2. A tokenizer and embedding graph turn each passage into text vectors.
  3. The language model predicts discrete speech tokens and reuses a 24-tensor key/value cache.
  4. The acoustic decoder turns the full token sequence into a 24 kHz waveform.

The decoder returns complete audio for one passage. It cannot play speech while that passage is being decoded. The reader splits text at punctuation and starts the next passage while the previous audio plays. This reduces wait between passages, but it can add pauses and prosody changes.

What small can mean

The selected quantized package is about 547 MiB across four graphs. That is small relative to multi-gigabyte speech models. It is still a large first download for a browser app. The conversion is experimental, and its reported WebGPU smoke test covers one Windows computer with an RTX 3060.

Browser inference has additional limits. WebGPU needs a supported browser, a compatible GPU and driver, and a secure context such as localhost. ONNX Runtime WebGPU supports a subset of ONNX operators. A successful session load does not prove that every operation ran on the GPU.

A streaming comparison

Kyutai Pocket TTS is another small voice-cloning model. Its upstream project reports audio streaming and a 200 ms first chunk on its supported Python path. The project lists community WebAssembly and ONNX Runtime Web ports, but does not officially support browser inference. Those latency claims are not browser measurements. Pocket TTS is a useful follow-up if the Nano passage queue leaves long gaps.

What this test measures

  • Model initialization and estimated time until scheduled playback.
  • Latest passage synthesis duration and total generated audio.
  • Mean real-time factor for the current reading session.
  • Playback continuity and voice quality through direct listening.

The page does not measure browser-process RSS or GPU memory. Those require process-level measurements. The reader can export synthesized chunks as a local mono PCM WAV with short edge fades. This reduces clicks. It cannot remove pauses or prosody changes between independently generated passages. The reported performance from this machine will not predict other devices. The original browser brief’s latency values are native-runtime results or targets, not browser measurements.
